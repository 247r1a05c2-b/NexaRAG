# NexaRAG 36-Hour Hackathon Guide

## First 2 hours

- Understand the problem statement.
- Identify users and the actual pain point.
- Decide what documents/data the system needs.
- Choose one measurable success criterion.
- Map the problem onto the NexaRAG RAG engine.

## Hours 2–8

Build the domain layer:

- specialized prompt
- domain-specific workflow
- input validation
- useful output format
- source citations

## Hours 8–16

Add one or two differentiating features:

- comparison
- structured extraction
- recommendations grounded in sources
- question generation
- analytics
- feedback loop

Do not add ten unfinished features.

## Hours 16–24

Stabilize:

- test normal inputs
- test empty documents
- test unsupported files
- test questions with no answer
- test multiple documents
- improve error messages
- verify source traceability

## Hours 24–30

Prepare the demo:

1. Problem
2. Solution
3. Architecture
4. Live workflow
5. Differentiator
6. Results
7. Future scope

## Hours 30–34

Prepare judge questions:

- Why RAG?
- Why not a normal chatbot?
- Why embeddings?
- Why Chroma?
- How do you reduce hallucinations?
- How do you handle irrelevant documents?
- How do you evaluate retrieval?
- What happens when the answer is not in the documents?
- How would you scale it?
- What makes your solution different?

## Hours 34–36

Freeze the build.

- Do not add risky features.
- Verify deployment.
- Verify API secrets.
- Keep a backup branch.
- Record a short demo video.
- Rehearse the 3-minute explanation.

## 3-minute pitch structure

### 0:00–0:30
State the problem and who has it.

### 0:30–1:15
Show NexaRAG ingesting the relevant documents.

### 1:15–2:00
Ask a real question and show the grounded answer with sources.

### 2:00–2:30
Explain the RAG architecture and differentiating feature.

### 2:30–3:00
State measurable impact, limitations, and future scope.

## Golden rule

A working, understandable product with one strong differentiator is more useful during a 36-hour event than a large collection of unfinished features.
